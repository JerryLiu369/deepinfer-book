# DeepInfer 学习书：执行规划与开工自检

## 1. 全书核心论点

DeepInfer 不是与 vLLM、SGLang 竞争生态覆盖面的通用分布式推理框架，而是 DeepSeek 围绕单一生产模型（DeepSeek-V4.1-Flash）、在特定的超大集群物理拓扑与架构切分（E/P/D 物理分离、Prefill 低 EP、Decode 宽 EP64–128、外置 3FS 存储持久化 KV cache 3–7 天）下，将每 token 边际服务成本压榨到极限的**专用生产推理引擎**。它的每一项核心机制——双硬件算子分发、ZOS 零开销批调度、FP4/MXFP4 激进量化、基于 CED 与 SWA 的 128 token 有界重放、结合置信度的 DSpark 动态验证——均是模型数学结构与硬件访存/通信瓶颈强行对齐的深度协同产物。专用性换来了极致吞吐与成本收益，但代价是彻底放弃了多模型通用性、剥离了完整在线服务配套，且高度依赖特定超节点集群架构。

## 3. 认为最难写好的三章与应对策略

### 3.1 第 3 章：认识它服务的模型：DeepSeek-V4.1-Flash（★★★）
- **难点**：涉及大量未在正式学术论文中全面公开的结构名称（YOCO、CED、Engram、mHC、MLA、跨层共享、SWA、混合精度格式）。极易被第三方营销号与二次报道误导（如虚构 CSA 机制、参数规模乱标），或陷入生硬术语堆砌。
- **应对策略**：
  1. 建立硬核准绳：参数与拓扑必须严格回溯 Hugging Face `config.json` 与 `model_executor/models/` 源码（A 级代码证据）。
  2. 结构强制对齐：每一项模型特征必须回答“这对推理引擎意味着什么”，并用显存带宽、计算密度与通信步数给出因果解释。
  3. 建立后续回指锚点：在章内给出结构化“模型特征 → 引擎设计”全局对照表，未能权威确认的术语坦白注明“代码内部命名，公开论文未详述”。

### 3.2 第 8 章：SWA 有界重放：只重算最后 128 个 token（★★★）
- **难点**：这是全书最具代表性的“模型算法与引擎调度深度协同”突破口，涉及滑动窗口注意力历史依赖、跨层状态补全和近似计算的精度代价，极易写成晦涩的数学公式或概念走过场。
- **应对策略**：
  1. 严格落地“问题 → 思路 → 做法 → 代价 → 对比”五步法，使用具体序列长度（如 4096）和 ASCII/Mermaid 矩阵注意力视野对比图，算清 140 token（128 窗口 + 6 投机回退 + 缓冲）与全量重算的真实显存流量账。
  2. 紧扣工程妥协：以 `yoco_equiv.py` 与 PPL 测试代码为证，正面讲清近似重建在数学上为何不完全等价、但工程上为何能换取 prefill 计算量减半。

### 3.3 第 14 章：与 vLLM、SGLang 的异同（★★★）
- **难点**：最容易退化成毫无深度的功能打勾表，或陷入脱离测试边界的“谁比谁快”口水战；三者演进迅速且共享底层算子库（FlashMLA/DeepGEMM/DeepEP），极易混淆调度优势与算子优势。
- **应对策略**：
  1. 架构哲学定调：从第一性原理“专用（专为一模型一架构削足适履）vs 通用（多模型高扩展抽象）”切入，阐明专用性带来的零抽象收益与生态代价。
  2. 三维度结构化解构：按调度（ZOS vs 异步批）、内存（外置 3FS + 静态槽 vs 树状缓存）、并行（Wide-EP + EPLB vs 传统并行）横向对比，先讲机制再讲为何不同。
  3. 严格边界约束：对所有吞吐与收入数据强制绑定测试硬件、并发度、Prefix 长度与测试主体，明确指出不可比因素，杜绝孤立数字对比。
