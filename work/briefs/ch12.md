# 第 12 章 简报：结果可信：批不变、确定性采样与结构化输出

## 在主线上的位置
技术篇第六章（★）。回答主线三个源头之三：“生产要什么——可复现性与格式正确”。剖析学术评测与生产交付中至关重要的正确性保障机制。内容属于 A 级源码事实。

## 核心问题
同样的 Prompt，在不同 Batch 大小或不同并发下为什么会产生不同的输出？DeepInfer 怎么保证结果绝对可复现与格式合规？

## 读完能说出（三句话）
1. 批不变推理（Batch-Invariant）通过消除浮点归约顺序对批大小的依赖（关闭 split-KV、split-K 与动态多重归约），保证了单请求结果与同批其他请求完全解耦。
2. 确定性采样基于请求绝对位置绑定伪随机数生成器（RNG），开启时必须关闭变长 MTP 以防止全批排名带来的交叉干扰。
3. 结构化输出基于上游 xgrammar 引擎自研了异步预编译线程池与投机掩码生成机制，确保每步输出均严格符合 JSON Schema 等语法自动机。

## 小节结构
### 12.1 批不变推理：浮点非结合律的工程反击
- 问题：浮点数加法不满足结合律（$(a+b)+c 
eq a+(b+c)$），Batch 大小变化改变归约顺序，如何做到结果完全不变？
- 思路：强制所有核心算子采用固定的单线程块归约路径，禁止切分批次并发。
- 做法：分析关闭 FlashMLA split-KV、DeepGEMM split-K 与 DeepEP 多重归约的具体代码开关。
- 代价：牺牲了部分 GPU 并行度与吞吐，CLI 明确标注 `(slower)`。
- 对比：浮点漂移不可复现 vs 逐 bit 绝对一致。
- 用到的事实：R11-#1

### 12.2 确定性采样与 RNG 定序
- 问题：开启并行与投机解码后，随机采样如何保证种子复现？
- 思路：将随机数生成器的状态直接与全局序列绝对位置（`seqlen_k`）强绑定。
- 做法：剖析 `sampler.py` 采样器，阐明为什么确定性采样必须强行关闭变长 MTP。
- 代价：无法享受变长投机带来的吞吐增益。
- 对比：依赖全局 RNG 状态流 vs 局部绝对位置单调流。
- 用到的事实：R11-#2

### 12.3 结构化输出：xgrammar 语法掩码与投机前瞻
- 问题：如何在极低延迟下强制大模型输出合法的 JSON 或代码语法？
- 思路：集成 xgrammar 语法引擎，在 GPU 采样前将非法 token 的 Logits 强行置为 $-\infty$。
- 做法：分析异步编译线程池、生成 pinned bitmask 以及配合投机解码预生成 $k+1$ 份掩码并支持回退的完整流程。
- 代价：首字生成前存在短暂的语法编译开销。
- 对比：后处理正则重试 vs 采样期即时 Logits 强力硬约束。
- 用到的事实：R11-#3

### 12.4 正确性基线：PPL 全等与 AIME 评测
- 问题：如何证明引擎没有在各种量化与算子融合中把模型精度“跑坏”？
- 思路：维护基准 PPL 指纹与 KL 散度全等测试；运行 AIME/GPQA 等严苛数学评测。
- 做法：分析 `offline_decode_ppl.json` 中的 60 个浮点指纹，展示 `eval/` 评测流程。
- 代价：需要定期维护回归评测流水线。
- 对比：凭感觉测试输出 vs 浮点级精准数值看门狗。
- 用到的事实：R11-#4, R11-#5
