# 第 2 章 简报：DeepInfer 是什么，不是什么

## 在主线上的位置
全书定位锚点章节。回答主线中的核心定位：DeepInfer 究竟开源了什么、保留了什么，以及为什么它是“专用生产引擎”而非“通用开源框架”。内容属于官方规范与代码事实（A/B 级）。

## 核心问题
DeepSeek 到底开源了什么？它与外界想象的“完整推理服务”有何本质区别？

## 读完能说出（三句话）
1. DeepInfer 是 DeepSeek 生产环境核心推理引擎的开源版本，专为 DeepSeek-V4.1-Flash 单一模型打造，仅支持 NVIDIA SM100 和华为昇腾 950 双硬件，且仅提供离线批推理接口。
2. 它不是开箱即用的 OpenAI 在线服务：KV cache 分布式存储系统（3FS）、P/D 物理分离集群调度、动态负载均衡器均未开源。
3. 它基于早期 vLLM 骨架改造而来，深度重写了调度与内核；与之同时开源的 deepseek-recipe 负责协议编解码与流式解析。

## 前置知识
第 1 章中关于推理引擎、Prefill/Decode、KV Cache 的基础概念。

## 小节结构
### 2.1 开源真相：发布背景与边界
- 问题：社区对 DeepInfer 的普遍期待是“一键拉起 DeepSeek 生产 API”，这是否符合现实？
- 思路：明确区分“开源的代码库”与“内部生产全套基础设施”。
- 做法：详细列出开源组件清单（离线引擎、TileLang 双硬件内核、C++ ZOS 调度）与未开源组件清单（3FS、P/D 编排、4 级 LB）。
- 代价：第三方无法直接用开源仓库搭建多租户在线 Web 服务。
- 对比：vLLM 的开箱即用 OpenAI API Server vs DeepInfer 的极简 `LLM.generate`。
- 用到的事实：R01-#1, R03-#7, R12-#1, R17-#1

### 2.2 苛刻的运行条件：单模型与双硬件
- 问题：为什么普通开发者无法在本地 4090 或 A100 上跑通 DeepInfer？
- 思路：引擎代码中深度硬编码了 V4.1-Flash 的架构常数与特定硬件能力（SM100 TMA 与昇腾 950 UB）。
- 做法：分析 `get_bf16_tflops_limit()` 硬件检测与架构断言，讲清非 SM100 报错退出机制。
- 代价：彻底放弃了硬件兼容性与消费级显卡生态。
- 对比：vLLM/SGLang 广泛支持各类 GPU/NPU/CPU vs DeepInfer 仅支持 2 款顶级芯片。
- 用到的事实：R03-#4, R10-#4, R18-#4

### 2.3 生产规模与官方动机
- 问题：DeepSeek 为什么要在特定节点开源这样一套专用引擎？
- 思路：引用官方 X 公告（降低社区算力与能源成本）与 2025 年“公开部署尚不现实”的真实历史语境。
- 做法：客观引述官方公布的生产指标：日服务 155 万亿 token、谷时定价下单 GPU 小时 38 美元收入。
- 代价：官方声明基于极致规模化与谷时电力，不可直接外推至小规模私有化集群。
- 对比：单机评测吞吐 vs 工业级超大集群综合利用率。
- 用到的事实：R01-#1, R01-#2, R16-#1

### 2.4 配套利器：deepseek-recipe 协议解析器
- 问题：大模型推理 API 中，特殊 token 注入和流式解析为什么必须独立成高性能模块？
- 思路：Python 层做分词与状态机开销巨大且易受恶意 prompt 注入。
- 做法：介绍 Rust 编写的 deepseek-recipe，阐述其多协议分段并行编码与 11 状态 KMP 流式解析器。
- 代价：需要额外编译 Rust 原生扩展并与 Python 绑定。
- 对比：传统 Python 正则/Tokenizer 包装 vs Rust 零开销协议层。
- 用到的事实：R12-#6
