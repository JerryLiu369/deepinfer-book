# 第 14 章 简报：与 vLLM、SGLang 的异同

## 在主线上的位置
全书第四大核心章节（★★★）。回答全书终极问题：“专用与通用的取舍”。从血统、架构、内核与性能全维度对比三大引擎。内容属于 A 级代码对比、B 级官方公告与综合分析。

## 核心问题
同样面对 DeepSeek-V4.1-Flash，DeepInfer、vLLM 和 SGLang 到底差在哪里？企业和开发者到底该选哪个？

## 读完能说出（三句话）
1. 三者的根本差异是架构哲学：DeepInfer 是专为单一模型打造的极致定制引擎，剥离了一切抽象；而 vLLM 和 SGLang 是服务全生态模型的通用引擎，必须背负泛化抽象包袱。
2. 三者存在深刻的血统渊源与算子共享：DeepInfer 骨架源自 v0.2.x 时代的 vLLM，调度借鉴了 SGLang；而 vLLM 和 SGLang 均深度集成了 DeepSeek 开源的 FlashMLA、DeepGEMM 与 DeepEP 核心库。
3. 选型指南：需要在线多租户服务、多硬件生态或多模型选 vLLM/SGLang；要在顶配集群（SM100/昇腾 950）上榨干 V4.1-Flash 极限吞吐或研究系统设计，读/用 DeepInfer。

## 小节结构
### 14.1 架构哲学：专用引擎 vs 通用框架
- 问题：为什么 DeepSeek 不直接在 vLLM 上做贡献，而要另起炉灶写一个 DeepInfer？
- 思路：通用框架需要支持数百个模型、几十种硬件和复杂在线功能，无法容忍将 128 窗口、890 字节布局或特定专家拓扑硬编码进引擎核心。
- 做法：对比三者的设计约束与目标边界。
- 代价：DeepInfer 换来了极致紧凑与零抽象开销，但彻底丧失了通用性。
- 对比：专线赛车 vs 全地形越野车。
- 用到的事实：R15-#1, R15-#4, R01-#1

### 14.2 血统溯源：剥开 DeepInfer 的 vLLM 外壳
- 问题：DeepInfer 中那 23 个标记为“Derived from vLLM”的文件到底改了什么？
- 思路：通过 Git 历史指纹比对，证实 DeepInfer 分叉自 vLLM v0.2.x 时代，呈现“壳留下、芯全换”的特征。
- 做法：详细分析 `llm_engine.py`、`worker.py`、`cache_engine.py` 的改动幅度，指出调度与内存管理已被 C++ 和 TileLang 全面替换。
- 代价：脱离了上游社区的持续维护主线。
- 对比：浅度修改分支 vs 深度换芯重构。
- 用到的事实：R15-#1, R15-#2, R03-#5

### 14.3 全维度技术对比：调度、内存、并行与投机
- 问题：在具体技术实现上，三大引擎在同一考题下交出了怎样的答卷？
- 思路：分维度逐项对比：调度（ZOS vs V1 EngineCore vs Overlap）、前缀缓存（外置 3FS vs Block Hash vs RadixAttention）、并行（Wide-EP vs TP+EP）、投机（DSpark 变长 vs Adaptive vs EAGLE）。
- 做法：编制详尽的技术维度横向对比矩阵，配文字深度解读。
- 代价：让读者看清各框架在不同技术路线上的取舍。
- 对比：机制级深度剖析，拒绝浮于表面的打勾表。
- 用到的事实：R13-#1~R13-#8, R14-#1~R14-#7, R15-#3

### 14.4 性能数字照妖镜：不可比的 6%
- 问题：vLLM 官方声称“解码吞吐已在 DeepInfer 6% 以内”，这个数据可信吗？
- 思路：严谨还原测试边界：vLLM 侧硬件拓扑未公布，且对比的是 DeepInfer 带有推导假设的 Pareto 曲线，两者并不具备绝对可比性。
- 做法：列举 7 项必须对齐的物理约束（硬件、拓扑、并发度、前缀命中率等），澄清第三方小集群实测与超节点测试的矛盾。
- 代价：戳破社区脱离前提盲目比拼数字的迷思。
- 对比：严谨科学对照 vs 营销宣传数字。
- 用到的事实：R13-#10, R16-#3, R16-#6

### 14.5 生态反哺与选型决策指南
- 问题：DeepInfer 开源后上游社区吸收了什么？我到底该用哪一个？
- 思路：vLLM 和 SGLang 正在快速吸收 DSpark 算子与 Engram 机制；给出分场景的具体选型决策树。
- 做法：绘制选型决策树，逐条给出企业落地与学术研究建议。
- 代价：没有放之四海而皆准的万能引擎。
- 对比：按需选型 vs 盲目跟风。
- 用到的事实：R13-#11, R14-#5, R17-#2
