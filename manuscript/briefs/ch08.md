# 第 8 章 简报：SWA 有界重放：只重算最后 128 个 token

## 在主线上的位置
全书最具技术代表性的核心章节（★★★）。回答主线三个源头之一与三：“模型结构（SWA+YOCO）与引擎极致协同”。详尽推导有界重放的数学原理、计算节省与精度验证。内容属于 A 级源码、测试脚本与 C 级精度证据。

## 核心问题
在缓存命中缺少局部 SWA KV 或跨层计算时，如何避免把长达数万 token 的历史全部重算一遍？

## 读完能说出（三句话）
1. 精确重建 SWA KV 需要把长历史重新跑过多层，计算量与历史长度线性相关；有界重放将注意力截断在最后 128 个 token 内，以**常数开销**生成高保真近似 SWA KV。
2. 它应用于两个关键场景：Encoder 层的缓存命中补算，以及 Decoder 层的 Prefill 计算（让 Decoder 算力需求骤降 98.6%，全模型 Prefill 算力接近减半）。
3. 这是算法结构（SWA + YOCO）与系统工程深度协同的典范，后训练阶段显式模拟了该截断行为，第三方评测证明其对模型精度影响处于统计误差范围内（<1.5 SE）。

## 小节结构
### 8.1 什么是 SWA，为什么历史重建代价高昂
- 问题：滑动窗口注意力（SWA）只看前 128 个 token，为什么精确恢复中间状态却需要向前回溯几千 token？
- 思路：深度多层网络中，每层感受野逐层累积，第 20 层的 128 窗口实际依赖最底层长达 2,560 token 的历史。
- 做法：用数学公式和感受野传播树展示“精确重建”为何导致计算量爆炸。
- 代价：全量重算使得长文本前缀缓存收益大打折扣。
- 对比：全量历史精确前向 vs 有界截断重放。
- 用到的事实：R07-#1, Q02

### 8.2 有界重放的数学思路：强制截断视界
- 问题：能不能直接把历史窗口强行斩断？数学上到底算什么？
- 思路：位置 $i$ 的 query 只与 $\max(s, i-127)$ 到 $i$ 的 key 做注意力，强行将重算区间框定在最后 128 个 token。
- 做法：展示注意力可见域公式与 `prepare_tensor_input_v4.cpp` 的 4 个 pivots 展开索引。
- 代价：截断导致网络失去了 128 token 之前的间接高阶感知，产生微弱特征近似。
- 对比：因果掩码三角矩阵 vs 有界带状截断矩阵。
- 用到的事实：R07-#2, R07-#3

### 8.3 两个战场的应用：命中补算与 Decoder Prefill 减半
- 问题：该技术在推理全流程的哪两处爆发了威力？
- 思路：战场一：前缀命中时无需回退整段上下文，仅补算最后 128 个 token；战场二：Decoder 层 Prefill 彻底抛弃前文，只跑末尾 `KEEP_TOKENS`。
- 做法：给出具体数值算式（$L=10,000$）：Decoder 算力从 200,000 行·层骤降至 2,800 行·层（省 98.6%），总 Prefill 算力减少 49.3%。
- 代价：Decoder 层在 Prefill 阶段无法建立前文词间的局部自注意力（但因已包含 Encoder 全局隐状态，语义得以维持）。
- 对比：全层全量 Prefill vs YOCO + 有界重放半程 Prefill。
- 用到的事实：R07-#1, R07-#4, R07-#7

### 8.4 精度等价性验证：模型会变笨吗？
- 问题：近似截断会不会损害大模型的逻辑推理与长文本召回能力？
- 思路：训练阶段主动引入截断噪音（Noise Injection）；开源代码 `yoco_equiv.py` 验证 Mask 与 Compact 算子等价性。
- 做法：引述 vLLM GSM8K/GPQA 评测实测数据（差异在 1.5 SE 内，基本等价）。
- 代价：后训练阶段需额外增加截断适应性调优。
- 对比：未经微调的硬截断崩溃 vs 训练-推理协同的无损截断。
- 用到的事实：R07-#5, R07-#6

### 8.5 vLLM 和 SGLang 怎么做
- 问题：通用引擎是否也集成了这套机制？
- 思路：vLLM 在 PR #58132 中实现了 YOCO Truncation；SGLang 在 V4.1 方案中作为特殊开关引入。
- 做法：对比各家在环境变量与算子实现上的跟进情况。
- 代价：通用框架默认关闭该特性，需手动配置。
- 对比：DeepInfer 原生核心机制 vs 通用引擎外挂插件。
- 用到的事实：R07-#6, R13-#9, R14-#5
